# 2026-09-10 작업 로그 (Phase 5: BitCtrl 시뮬레이션 검증 + ByteCtrl RTL/TB + I2cMaster 착수)

## 오늘 한 일

### 1. BitCtrl.vhd 시뮬레이션 실제 검증
- Vivado 시뮬레이션 진행 중 `PROCESS(ALL)`이 VHDL-2008 전용 문법이라 컴파일 에러 → sensitivity list를 명시적으로 나열하는 방식으로 수정
- 파형으로 SCL 주기 확인하다가 **설계 결함 발견**: `T_LOW=65`, `T_SETUP=5`, `T_HIGH=30` 조합으로는 SCL 주기가 약 2.06us(≈485kHz)가 되어 24LC256 Fast-mode 최대 주파수(400kHz, 최소 주기 2.5us) 스펙 위반 — 개별 `TLOW`/`THIGH` 최소값은 만족해도 합산 주기가 부족했던 문제. Phase3 문서엔 없던 새 체크 항목이었음
  - `T_LOW`를 65→90으로 올려서 전체 주기 128사이클(2.56us)로 스펙 통과하도록 수정
- I2C START 조건(SCL High 유지 중 SDA가 반드시 High→Low로 "전환"되어야 함, 단순 Low 유지는 START로 인식 안 됨), `SdaLatch`가 `SdaOut`이 아니라 `SdaIn`(실제 수신값)을 래치한다는 개념 정리

### 2. 아키텍처 재변경: 3계층 nested → 2계층 flat(형제) 구조
- `ByteCtrl` 안에 `BitCtrl`을 nested시키는 기존 구조를 버리고, **`I2cMaster`가 `BitCtrl`/`ByteCtrl`을 나란히 형제로 직접 인스턴스화**하는 구조로 변경 (애초에 권장했던 방식으로 회귀)
- 장점: `I2cStart`/`I2cStop`/`SclOut`/`SdaOe`/`SdaOut`/`SdaIn`을 `ByteCtrl`이 그냥 통과만 시키던 pass-through 포트가 전부 사라짐
- 대신 `TxBit`이 `ByteCtrl`의 실제 출력 포트로 승격됨(이전엔 nested라 내부 신호로만 존재)

### 3. ByteCtrl.vhd RTL 코딩 (신규 파일)
2-process 스타일로 직접 작성, 리뷰 반복하며 다음 문제들을 순차적으로 발견·수정:
- `IN` 포트(`ByteStart`)에 대입하던 컴파일 불가 버그 (`BitStart`와 이름 혼동)
- `Cnt`가 Counter 프로세스와 comb 프로세스 양쪽에서 동시에 구동되던 다중 드라이버 문제
- `Cnt`가 상태 유지 중 매클럭 감소하던 구조 → `BitDone='1'`일 때만 감소하도록 재설계
- `SHIFT_BIT`에서 `BitDone` 체크 없이 매클럭 `BitStart` 재트리거하던 버그
- 시프트 연산에 `AND` 대신 `&`(연결) 연산자 사용 오류, `~`(Verilog 문법) → `NOT` 수정
- `TxBit` 읽기 타이밍이 한 클럭 밀리는 stale-read 버그(`DataReg(7)`→시프트 후 값을 읽으려면 `DataReg(6)`으로 당겨 읽어야 함), `LOAD`에서 첫 비트용 `TxBit` 누락
- `LOAD`/`DONE` 상태에서 `StateN`을 안 정해줘서 FSM이 해당 상태에 영원히 갇히던 버그 (2차례, 각 상태마다 반복 발생)
- comb 프로세스 sensitivity list 누락(`ByteStart`/`Cnt`/`BitDone`), 출력 신호 6종 디폴트 누락으로 인한 래치 추론(`ByteDone`이 한번 뜨면 안 꺼지는 등)
- 최종적으로 모든 문제 해결, Write 경로 로직 완성

### 4. ByteCtrlTb.vhd 테스트벤치 작성 및 디버깅
- 뼈대 작성(클럭 생성, DUT 연결, `BitDone`을 8+1회 흉내내는 `FOR` 루프)
- `SysClk` 초기값 미설정으로 `'U'`에 고정되어 클럭이 아예 안 도는 문제, 마무리 `WAIT;` 누락으로 무한 반복하는 문제 수정
- Vivado가 소스 수정 후 자동 재컴파일 안 해줘서 "Relaunch Simulation" 필요하다는 점 확인 (Restart만으로는 옛날 컴파일 결과로 계속 시뮬레이션됨)
- **델타 사이클 레이스 컨디션 2종 발견**:
  1. `WAIT FOR CLK_PERIOD*5`가 정확히 클럭 엣지에 딱 맞아떨어져서 `BitDone` 대입이 DUT의 클럭 샘플링과 레이스 → 엣지에서 벗어나게 오프셋(`+ CLK_PERIOD/4`) 추가
  2. `BitStart`가 조합회로라 `BitDone`이 꺼지는 즉시 같이 꺼져버려서, `WAIT UNTIL BitStart='1'` 같은 이벤트 기반 대기가 짧은 펄스를 놓치고 영원히 멈추는 문제 → 매 클럭 엣지마다 값을 폴링(`LOOP + WAIT UNTIL rising_edge + EXIT WHEN`)하는 방식으로 전환
- (진행 중) 최종 수정 반영 후 재검증 필요
