### 2. 아키텍처 최종 확정
- 4계층 중첩 컴포넌트 구조로 확정: `TpgCtrlTop → EepRomCtrlTop → I2cMaster → ByteCtrl → BitCtrl`
- 이름 정리: `BitTxRx→BitCtrl`, `ByteData_FSM→ByteCtrl` (I2cMaster와 이름 체계 통일)
- `TpgCtrlTop_Block_Diagram2.drawio`에 최종 구조로 블록 다이어그램 재작성, 신호 방향 전부 재확인
- **`TxBit` 신호 신규 발견**: `ByteCtrl`이 `BitCtrl`에게 "이번에 보낼 비트 값"을 전달할 방법이 원래 설계엔 없었음(`DriveEn`은 구동 여부만 결정, 값은 못 정함) → `ByteCtrl→BitCtrl` 방향 `TxBit` 신호 추가로 확정 (설계상 필수, 기존 문서 소급 반영은 선택으로 보류)

### 3. Phase 5 착수 — BitCtrl.vhd RTL 코딩
2-process 스타일(`c_state`/`n_state`)로 직접 작성, 리뷰하며 다음 문제들을 순차적으로 발견·수정:
- 상태 레지스터만 있고 타이밍 카운터(`Cnt`)를 구동하는 코드가 아예 없던 문제
- 카운터 리셋 로직을 comb 프로세스에 넣어 `Cnt`가 두 프로세스에서 동시에 구동되던 문제(다중 드라이버) → seq 프로세스 안으로 통합
- `nRST`/`rising_edge` 체크 순서가 뒤바뀌어 리셋이 제대로 안 걸리던 구조적 오류
- comb 프로세스에서 `SclOut`/`SdaOe`/`SdaOut`/`BitDone`/`SdaLatch`에 디폴트 대입이 없어 래치가 추론되던 문제(`BitDone`이 펄스가 아니라 계속 `'1'`로 래치되는 등) → CASE 진입 전 전체 디폴트 `'0'` 대입으로 해결
- `TxBit` 포트를 선언만 하고 실제로 안 쓰던 문제(`SdaOut`이 항상 0) → 데이터 비트 구간(`SCL_LOW`/`SDA_SETUP`/`SCL_HIGH`)에 `SdaOut <= TxBit` 추가
- `SclOut`이 계속 `'0'` 고정이던 문제 → 상태별로 표에 맞게 `'1'`/`'0'` 반영, 전체 FSM 로직 완성

### 4. BitCtrlTb.vhd 테스트벤치 뼈대 작성
- `entity work.BitCtrl port map(...)` 직접 인스턴스화 방식으로 DUT 연결, 50MHz 클럭 생성
- 테스트 시나리오 3종 작성: Write 비트 1개 전송, `I2cStart`(START 조건), `I2cStop`(STOP 조건) — `WAIT UNTIL BitDone='1'` 패턴으로 대기
