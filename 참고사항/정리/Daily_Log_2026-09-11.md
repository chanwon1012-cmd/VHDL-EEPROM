# 2026-09-11 작업 로그 (Phase 5: I2cMaster.vhd RTL 착수)

## 오늘 한 일

### 1. I2cMaster.vhd 1차 골격 리뷰 — 컴파일 자체가 안 되는 수준의 문제 다수 발견
- `BitCtrl`/`ByteCtrl` `COMPONENT` 선언은 있는데 실제 인스턴스화(포트맵) 코드가 아예 없던 상태 → 이후 인스턴스화 코드는 작성됐으나:
  - `GENERIC MAP(generics)` — 자리표시자 텍스트가 실제 코드처럼 남아있던 문제 (제네릭 전부 기본값 있으니 통째로 삭제 가능)
  - `BitCtrl_Inst`/`ByteCtrl_Inst` 포트맵에서 `SdaIn`/`SclOut`/`SdaOe`/`SdaOut`/`rw`/`WriteData`/`BitDone`/`ByteDone`/`ReadData`/`Ack`/`BitStart` 등 다수 포트가 값 없이 비어있던 문제, 쉼표 누락
  - `ByteStart => BitStart`로 잘못 연결 — `ByteStart`(바이트 단위 트리거)와 `BitStart`(비트 단위 트리거)는 완전히 다른 신호인데 혼동
  - `ByteStart`/`rw`/`ACK` 신호가 architecture 선언부에 아예 없어서(선언 누락) 컴파일 에러

### 2. FSM 본체(CASE) 1차 작성 후 리뷰
- `IDLE`부터 `READ_DATA`까지 전체 상태 채워짐, Phase4 ③번 표 흐름은 대체로 맞게 옮겨짐
- 발견된 문제:
  - `STOP` 상태에서 `StateN`을 안 정해줘서 FSM이 갇히는 버그 (ByteCtrl의 `LOAD`/`DONE`에서 이미 2번 겪었던 패턴이 3번째로 재발)
  - `I2cStart`/`I2cStop`/`Busy` 등 출력 디폴트가 전혀 없어 래치 위험 (`I2cStart`가 한번 뜨면 안 꺼지는 문제 등, BitCtrl/ByteCtrl 때와 동일 클래스)
  - **`ByteCtrl`을 실제로 시작시키는 `ByteStart<='1'` 펄스가 어디에도 없다는 근본적인 누락 발견** — 지금 상태로는 ByteCtrl이 절대 안 움직여서 `ByteDone`이 영원히 안 뜸

### 3. `ByteStart`/`rw` 설계 방향 정리 (개념 설명, 코드는 직접 작성 중)
- `ByteStart`는 I2cMaster 자체 FSM이 만들어야 하는 신호이며, **"다음 상태가 바이트-전송 상태(CTRL_BYTE/ADDR_H/ADDR_L/DATA/CTRL_BYTE_R/READ_DATA)로 정해지는 그 전이(transition) 순간"**에 펄스로 쏴야 한다는 패턴 확인 (ByteCtrl의 `SHIFT_BIT`가 다음 비트로 넘어가며 동시에 `BitStart`를 쏘던 패턴과 동일 원리)
- `rw` 방향 규칙 재확인: 컨트롤바이트/주소 바이트는 Read/Write 무관하게 항상 Write 방향(`rw='0'`) — `CTRL_BYTE_R`(0xA1 전송)도 마스터가 그 바이트 값 자체를 "쓰는" 것이므로 Write 방향. 오직 `READ_DATA`(실제 데이터 8비트를 슬레이브가 미는 구간)만 `rw='1'`
- `ByteStart`/`rw`/`WriteData` 세 신호는 항상 세트로 같이 세팅해야 한다는 점 확인
- (선택, 미반영) `Phase4_FSM설계.md`의 I2cMaster 표에 `ByteStart` 출력이 안 적혀있음 — `TxBit` 때와 동일하게 소급 반영은 보류

## 다음에 이어서
- `ByteStart`/`rw`/`WriteData` 세트를 6개 전이 지점(START→CTRL_BYTE, CTRL_BYTE→ADDR_H, ADDR_H→ADDR_L, ADDR_L→DATA/REP_START, REP_START→CTRL_BYTE_R, CTRL_BYTE_R→READ_DATA) 전부에 채우기
- `STOP`의 `StateN<=IDLE` 누락, 전체 출력 디폴트 누락 수정
- 포트맵 빈 칸/쉼표 누락 수정, `ByteStart`/`rw`/`ACK` 신호 선언 추가
- NACK(ACK==0) 6곳 분기 로직 추가 (아직 미착수)
- 이후 I2cMaster 자체 TB 작성 → 검증
